# 풀카운트 v0.2 업데이트 프롬프트

v0.1(한 타석)을 바탕으로 "한 경기" 버전을 만드는 코드 작업용 프롬프트다. 아래 프롬프트를 **순서대로 하나씩** 코드 작업에 붙여 넣는다. 한 단계가 끝날 때마다 iPad에서 열어 확인하고 다음 단계로 넘어간다.

- 매 프롬프트 맨 앞에 **0. 공통 머리말**을 같이 붙인다.
- 한 번에 여러 단계를 붙이지 않는다. 한 단계씩 해야 문제가 생겼을 때 원인을 찾기 쉽다.
- 버그가 나오면 맨 아래 **버그 수정 프롬프트** 틀을 쓴다.

| 순서 | 단계 | 분야 |
| --- | --- | --- |
| 1 | 코드 파일 나누기 | 기술 |
| 2 | 한 경기 규칙(이닝, 주자, 점수, 공수 교대) | 경기 기능 |
| 3 | 투수 시점 투구 + 전체 구종 + 선수별 특징 | 조작 |
| 4 | 판정 폭 넓히기 + 존 끝으로 갈수록 확률 낮추기 | 밸런스 |
| 5 | 선수 모델과 유니폼 | 그래픽 |
| 6 | 담장, 관객, 관객석 위 전광판 | 그래픽 |
| 7 | 밤낮 모드와 야간 조명 | 그래픽 |
| 8 | 공 궤적 잘 보이게 | 그래픽 |
| 9 | 수비수와 주자 애니메이션 | 애니메이션 |
| 10 | 시작 메뉴와 결과 화면 | 화면 |
| 11 | 사운드(타격음, 관중 함성, 심판 콜) | 사운드 |

순서 이유: 2번(주자·점수)이 있어야 9번(주자 달리기)과 6번(전광판 점수)을 만들 수 있고, 3·4번 조작이 정해져야 그래픽을 붙였을 때 화면 배치가 흔들리지 않는다.

## 0. 공통 머리말 (매번 맨 앞에 붙이기)

```
나는 개발이 처음인 사람이고, iPad Safari에서 혼자 플레이할 야구 게임 "풀카운트"를 만들고 있어.
- 현재 코드: v0.1 index.html (Babylon.js 7.20.0을 https://cdn.jsdelivr.net/npm/babylonjs@7.20.0/babylon.js 에서 불러오는 웹페이지)
- 플랫폼: iPad Safari, 가로 화면, 터치 전용. 앱 설치 없이 웹페이지로 실행.
- 그림 스타일: 카툰 3D. 실존 구단·선수·로고는 쓰지 않고 가상 팀을 쓴다.
- 게임 성격: 구종 예측 같은 수 싸움 없이, 타이밍과 터치 조준으로 치고 던지는 손맛 중심.
- 외부 파일(이미지, 소리, 3D 모델)은 다른 서버에서 불러오지 말고, 코드로 만들거나 파일 안에 넣어줘.
- 출시하지 않는 개인 프로젝트라 수익화, 로그인, 서버는 필요 없어.

작업 방식:
- 이번 단계에서 요청한 것만 바꾸고, 이미 되는 기능은 망가뜨리지 마.
- 바꾼 파일 전체를 보여주고, 무엇을 왜 바꿨는지 쉬운 말로 짧게 설명해줘.
- 끝나면 iPad에서 직접 확인할 항목을 체크리스트로 알려줘.
```

## 1. 코드 파일 나누기

```
v0.1 index.html은 한 파일에 600줄이 넘어. 앞으로 기능이 많이 늘어날 거라 파일을 나눠줘.

- 빌드 도구(npm, Vite 등) 없이, index.html에서 <script src="js/파일.js"> 로 순서대로 불러오는 방식으로 해줘.
- 나누는 기준 예시: data/pitches.js(구종), data/teams.js(팀·선수), scene.js(구장·조명), players.js(선수 모델), pitching.js(투구), batting.js(타격·타구), game.js(경기 진행·규칙), ui.js(화면·전광판), audio.js(소리).
- 아직 내용이 없는 파일은 만들지 마. 지금 있는 코드만 옮겨.
- 기능은 하나도 바뀌면 안 돼. 나눈 뒤에도 v0.1과 똑같이 동작해야 해.
- 각 파일 맨 위에 이 파일이 맡는 일을 한 줄로 적어줘.
```

확인: 타격·투구 모드가 v0.1과 똑같이 되는지.

## 2. 한 경기 규칙

```
지금은 한 타석씩만 반복돼. 이걸 "한 경기"로 바꿔줘.

- 내 팀 vs 컴퓨터 팀. 내 팀이 공격일 때는 내가 타격, 수비일 때는 내가 투구.
- 이닝 수는 3이닝 또는 9이닝 중 고를 수 있게 (기본 3이닝). 원정팀이 초에 공격.
- 3아웃이면 공수 교대. 마지막 이닝 말에 홈팀이 앞서면 그 자리에서 경기 종료. 동점이면 연장 없이 무승부.
- 각 팀 타순 9명. 타석이 끝나면 다음 타자로 넘어감.
- 주자와 진루: 1루타·2루타·3루타·홈런·볼넷에 맞게 주자가 진루하고 득점이 계산되게. 일단 규칙은 단순하게: 안타는 모든 주자가 타자와 같은 수만큼 진루, 볼넷은 밀어내기만.
- 땅볼 아웃 때 1루 주자가 있고 0·1아웃이면 일정 확률(30%)로 병살.
- 화면 위 전광판에 이닝(초/말), 점수, 주자 상황(다이아몬드에 1·2·3루 불), 볼·스트라이크·아웃이 보이게.
- 3루타는 타구가 외야 깊은 곳(90m 이상)이고 펜스를 넘지 않은 경우 일부 확률로 나오게.
- 경기 규칙과 상태(이닝, 점수, 주자, 카운트)는 game.js 한 곳에서만 관리해줘.
```

확인: 3아웃 뒤 공수가 바뀌는지, 주자가 있을 때 안타가 나면 점수가 오르는지, 경기가 끝나는지.

## 3. 투수 시점 투구 + 전체 구종 + 선수별 특징

```
투구를 바꿔줘.

[투수 시점]
- 내가 투구할 때는 카메라를 투수 뒤쪽 어깨 높이에 두고, 포수 미트와 스트라이크존이 보이게 해줘.
- 존이 멀어서 작게 보이니까 카메라 시야를 좁혀서(줌) 존이 화면 가운데 충분히 크게 보이게.
- 조준은 화면의 존 위를 손가락으로 누른 채 움직이고, 지금처럼 줄어드는 링이 맞을 때 손을 떼면 던지게.
- 타격할 때는 지금처럼 포수 뒤 시점 유지.

[전체 구종]
data/pitches.js에 실제 야구 구종을 모두 넣어줘. 각 구종마다 이름, 평균 구속(km/h), 좌우 변화, 상하 변화, 꺾이는 시점(빨리/늦게)을 넣어줘.
포심 패스트볼, 투심 패스트볼, 싱커, 커터, 슬라이더, 스위퍼, 커브, 너클 커브, 슬러브, 체인지업, 서클 체인지업, 스플리터, 포크볼, 너클볼(불규칙하게 흔들림), 스크루볼, 팜볼, 이퓨스(아주 느린 포물선).
- 좌투수는 좌우 변화 방향이 반대가 되게.

[선수별 특징]
data/teams.js에 가상 팀 2개를 만들어줘. 팀마다 이름, 팀 색 2개, 타자 9명, 선발 투수 1명, 불펜 투수 2명.
- 투수: 이름, 좌/우투, 구속 보정, 제구(0~100), 체력(0~100), 쓸 수 있는 구종 3~5개와 구종별 숙련도(0~100). 숙련도가 높으면 변화가 크고 제구가 좋음.
- 타자: 이름, 좌/우타, 컨택(0~100), 파워(0~100), 선구안(0~100), 주력(0~100).
- 투구 화면 아래 구종 카드는 지금 투수가 가진 구종만 보여줘.
- 내가 타격할 때 상대 투수도 자기 구종 중에서 던지게.
- 컴퓨터 타자는 능력치에 따라 스윙·컨택·타구 질이 달라지게.
- 투수 체력: 투구 수가 늘면 제구 링이 더 빨리 줄어들고 구속이 조금 떨어지게. 수비 중에 "투수 교체" 버튼으로 불펜 투수로 바꿀 수 있게.
```

확인: 투수 시점에서 존이 잘 보이는지, 구종 카드가 투수마다 다른지, 너클볼이 흔들리는지.

## 4. 판정 폭과 존 끝 확률

```
조작 밸런스를 바꿔줘.

[타격 판정 폭 넓히기]
- 지금 타격 성공 판정 폭(시간 폭, 위치 폭)이 좁아. 루키 기준 시간 폭은 약 1.3배, 위치 폭은 약 1.3배로 넓혀줘.
- 이 값들은 파일 맨 위 설정값으로 모아서 내가 숫자만 바꿔 조절할 수 있게 해줘.

[존 끝으로 갈수록 치기 어렵게]
- 공이 스트라이크존 가운데에서 멀어져 끝(테두리)에 가까워질수록, 타자가 맞혀도 좋은 타구가 나올 확률이 낮아지게.
- 내가 타격할 때: 끝 공일수록 타구 속도가 줄고 파울·빗맞은 타구가 늘게.
- 컴퓨터 타자가 칠 때: 끝 공일수록 헛스윙·파울·약한 타구가 늘게.
- 가운데 공은 반대로 잘 맞게. (가운데 실투는 장타 위험)

[존 끝으로 갈수록 던지기 어렵게]
- 내가 투구할 때 조준점이 존 끝에 가까울수록 실제로 그곳에 들어갈 확률이 낮아지게.
  예: 조준점이 끝에 가까울수록 링이 맞는 구간이 좁아지거나, 같은 정확도라도 빗나가는 거리가 커지게.
- 투수의 제구 능력치와 구종 숙련도가 높으면 이 어려움이 줄어들게.
- 컴퓨터 투수도 같은 규칙을 따라서, 끝을 노리다 볼이 되거나 가운데로 몰리는 실투가 나오게.
```

확인: 가운데 공은 잘 맞고 끝 공은 잘 안 맞는지, 끝을 노리면 볼이 자주 나오는지.

## 5. 선수 모델과 유니폼

```
선수 모양을 바꿔줘. 지금은 캡슐에 공 머리라서 사람 같지 않아.

- 카툰 스타일은 유지하되 사람처럼 보이게: 머리, 목, 몸통, 위팔·아래팔, 손, 허벅지·종아리, 신발을 따로 만든 간단한 도형 조합으로.
- 관절(어깨, 팔꿈치, 엉덩이, 무릎)마다 회전할 수 있게 뼈대처럼 부모-자식 구조로 만들어줘. 나중에 투구·스윙·달리기 애니메이션에 쓸 거야.
- 글러브(수비수, 투수), 포수 장비(마스크, 미트), 배트, 헬멧(타자·주자)도.
- 유니폼: 팀 색으로 상의·하의·모자·양말. 홈팀은 흰 바탕 + 팀 색 줄무늬, 원정팀은 팀 색 바탕. 등번호와 가슴 팀 이름은 코드로 그린 텍스처(DynamicTexture)로.
- 얼굴은 눈·눈썹 정도만 간단히.
- 선수 수가 많아지니까 iPad에서 느려지지 않게 같은 모양은 인스턴스나 복제로 재사용해줘.
```

확인: 타자·투수·포수가 사람처럼 보이는지, 두 팀 유니폼이 구분되는지, 화면이 끊기지 않는지.

## 6. 담장, 관객, 전광판

```
구장을 꾸며줘.

[담장]
- 외야 담장을 제대로: 파울 폴 2개, 담장 위 노란 홈런 라인, 펜스 거리 표시(좌·우 98m, 중앙 122m 정도). 담장 높이는 3m.
- 홈런 판정도 이 담장 모양에 맞춰줘.

[관객]
- 내야·외야 관중석을 계단식으로 만들고 관객을 채워줘.
- 관객은 성능을 위해 아주 단순한 모양(몸통+머리)으로 하고, 인스턴스로 수천 명을 그려도 iPad에서 느려지지 않게.
- 옷 색은 여러 가지로 섞되 홈팀 색이 많게.
- 안타·홈런 때 관객이 들썩이게(위아래로 살짝 뛰기).

[관객석 위 전광판]
- 중앙 외야 관중석 위에 큰 전광판을 세워줘.
- 전광판에 실시간으로: 이닝별 점수표(라인 스코어), 총점, 안타 수, 현재 볼·스트라이크·아웃, 지금 타자 이름과 이번 경기 기록, 투수 이름과 투구 수, 마지막 투구 구종·구속.
- 코드로 그린 텍스처(DynamicTexture)로 만들고, 상태가 바뀔 때만 다시 그려줘.
- 화면 위 작은 전광판(HUD)도 유지.
```

확인: 홈런이 담장을 넘을 때 판정이 맞는지, 관객이 있어도 끊기지 않는지, 전광판 숫자가 바로 바뀌는지.

## 7. 밤낮 모드와 야간 조명

```
낮 경기와 밤 경기를 만들어줘.

- 경기 시작 전에 "낮 / 밤"을 고를 수 있게 (메뉴는 10단계에서 만들 거라 일단 설정값으로).
- 낮: 지금처럼 하늘색 하늘, 해 조명.
- 밤: 어두운 남색 하늘, 별 몇 개, 해 대신 조명탑.
- 조명탑: 내야·외야에 4~6개를 세우고, 밤에는 램프가 켜지면서 빛이 경기장을 비추게. 램프에 빛나는 효과(GlowLayer)를 넣어줘.
- 밤에는 전광판과 관객석도 조명에 맞게 보이게.
- iPad 성능을 위해 실제 그림자 계산은 쓰지 말고, 필요하면 선수 발밑에 가짜 원형 그림자만.
```

확인: 밤 경기에서 공이 잘 보이는지(공이 안 보이면 8단계에서 같이 해결).

## 8. 공 궤적 잘 보이게

```
던진 공과 타구가 더 잘 보이게 해줘.

- 공을 조금 더 크게 보이게(실제 크기의 약 1.5배) 하고, 공 둘레에 얇은 밝은 테두리나 빛 효과.
- 공 뒤에 짧은 꼬리 궤적(TrailMesh)을 그려줘. 투구는 흰색, 타구는 노란색.
- 구종마다 꼬리 색을 살짝 다르게 하는 옵션(설정값으로 켜고 끄기).
- 타구가 뜨면 땅에 공 그림자와 떨어질 지점 표시를 같이 보여줘.
- 밤 경기에서도 잘 보여야 해.
- 꼬리 궤적은 끄고 켤 수 있게 설정값으로.
```

확인: 루키·프로 속도 모두에서 공을 눈으로 따라갈 수 있는지.

## 9. 수비수와 주자 애니메이션

```
수비와 주루를 움직이게 해줘. 5단계에서 만든 관절 구조를 써.

[수비수]
- 9명 수비수를 기본 위치에 세워줘.
- 타구가 뜨면 가장 가까운 수비수가 떨어질 지점으로 달려가고, 잡으면 글러브 위치로 공이 들어가게.
- 땅볼은 내야수가 달려가 잡고 1루로 던지는 동작. 공이 실제로 1루수에게 날아가게.
- 안타면 외야수가 공을 쫓아가 주워서 내야로 던지게.
- 다이빙 캐치는 공이 아슬아슬하게 닿을 때만.
- 결과(아웃/안타)는 지금처럼 판정 코드가 먼저 정하고, 애니메이션은 그 결과에 맞춰 보여주는 방식으로. (애니메이션 때문에 결과가 바뀌지 않게)

[주자]
- 타자가 치면 배트를 던지고 1루로 달리게. 주자는 주력 능력치에 맞는 속도로 베이스를 돌아 진루.
- 홈런이면 천천히 베이스를 한 바퀴 돌게(빨리 감기 버튼 제공).
- 아웃된 주자는 더그아웃 쪽으로 걸어 나가게.

[달리기 동작]
- 팔·다리를 번갈아 흔드는 달리기, 수비수 준비 자세, 투수 와인드업, 타자 스윙을 관절 회전으로.

[카메라]
- 타구가 나면 카메라가 공과 주자가 잘 보이는 위치로 부드럽게 따라가고, 플레이가 끝나면 원래 시점으로.
- 너무 길어지지 않게 한 플레이는 최대 6초 정도로, 화면을 탭하면 건너뛰기.
```

확인: 땅볼 아웃, 뜬공 아웃, 안타, 홈런 때 움직임이 결과와 맞는지, 탭하면 건너뛰는지.

## 10. 시작 메뉴와 결과 화면

```
시작 메뉴와 경기 결과 화면을 만들어줘. 게임 모드는 "한 경기" 하나만 있어.

[시작 메뉴]
- 게임 제목 "풀카운트"
- 내 팀 고르기 (2팀 중 하나, 팀 색과 이름 카드로)
- 홈/원정 고르기
- 이닝 수 (3이닝 / 9이닝)
- 낮 / 밤
- 난이도 (루키 / 프로)
- "경기 시작" 버튼
- 마지막에 고른 설정은 localStorage에 기억해서 다음에 그대로 나오게 (실패해도 게임은 되게 try/catch).

[경기 중]
- 오른쪽 위에 일시정지 버튼: 이어하기 / 처음으로.

[결과 화면]
- 승/패/무 크게 표시
- 라인 스코어(이닝별 점수, 득점·안타)
- 내 타자 기록: 타수, 안타, 홈런, 타점, 삼진
- 내 투수 기록: 이닝, 투구 수, 피안타, 실점, 탈삼진
- 이번 경기 가장 긴 홈런 거리, 가장 빠른 타구 속도
- "다시 하기" / "메뉴로" 버튼

- 버튼은 iPad 손가락으로 누르기 쉽게 48px 이상.
```

확인: 메뉴에서 고른 설정이 경기에 반영되는지, 경기가 끝나면 결과 화면이 나오는지.

## 11. 사운드

```
소리는 세 가지만 넣어줘: 타격음, 관중 함성, 심판 콜.

- 외부 소리 파일 없이 Web Audio API로 코드에서 만들어줘.
- 타격음: 정타는 "딱!" 하는 맑은 소리, 빗맞으면 둔한 소리, 파울은 짧은 소리. 타구 질에 따라 달라지게.
- 관중 함성: 평소엔 작은 웅성거림(노이즈로), 안타·홈런·삼진 때 커지는 함성. 홈런은 가장 크게.
- 심판 콜: "스트라이크!", "볼!", "아웃!", "세이프!"를 짧게. 브라우저 음성 합성(speechSynthesis)을 쓰되, 안 되면 소리 없이 넘어가게.
- iPad Safari는 사용자가 화면을 한 번 터치해야 소리가 나니까, 시작 메뉴의 "경기 시작" 버튼을 누를 때 오디오를 켜줘.
- 메뉴와 일시정지 화면에 소리 켜기/끄기, 음량 조절.
```

확인: iPad에서 소리가 나는지(무음 모드 스위치도 확인), 심판 콜이 너무 늦지 않은지.
